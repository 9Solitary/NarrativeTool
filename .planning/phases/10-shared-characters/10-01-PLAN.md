# Phase 10 Plan 01: 共享角色表（SHR-01）

## Objective

Narrative Canvas 打开任意 .ncanvas 时，vault `Characters/*.md` 的角色立即可用（补全/cast/自动打标）；导出引擎能解析指向共享角色的 cast 引用。

## 契约（两侧共同遵守）

- 共享角色 ID = `gc-` + frontmatter `id`（无 id 时退化为文件 basename）
- name 取 frontmatter `name`（无则 basename）；role/voice 取 frontmatter 同名字段
- NC 侧：共享角色只存 `state.sharedCharacters`（session 态），**永不写入** `state.project.characters`（防泄漏进 .ncanvas）
- 引擎侧：`exportEngine(json, { externalCharacters: [{id, name}] })` 纯注入，引擎保持零 obsidian 依赖

## Workstream A: NarrativeCanvas 插件（上游 vendored 副本）

### A1. 包装层 main.js
- `require('obsidian')` 已在 main.js:1；扫描用 `this.app.metadataCache.getFileCache(file)?.frontmatter`（免手写 YAML 解析）
- `Plugin.onload()`（main.js:96）：初次扫描 `Characters/*.md`（目录可配置，见 A4）；注册 vault `create/modify/delete/rename` 监听（先例 main.js:134-141），变更时重新扫描并调用 `window.NarrativeCanvasApp.refreshSharedCharacters?.()`
- host 接口（main.js:892-911 `NarrativeCanvasView.onOpen()`）加 `loadSharedCharacters: () => this.plugin.getSharedCharacters()`，返回 `[{id, name, role, voice, sourcePath}]`

### A2. app.js 核心
- `state.sharedCharacters`（resetRuntimeState 初始化）
- `getCharacters()`（app.js:24918）返回**缓存的合并数组**（project.characters ∪ sharedCharacters，shared 项带 `shared: true` 标记）；缓存在 `invalidateCharacterRenderContext()`（5498）一并失效——不得每次新建数组（getCharacterIndex 25008 / getCharacterMentionContext 25133 用引用相等做缓存）
- `NarrativeCanvasApp` 导出表（2226-2242）加 `refreshSharedCharacters()`：拉 host 数据 → 失效缓存 → 刷新角色页/cast 相关表面（参考 renderCharacterAwareSurfaces 15142）
- web 环境天然 no-op（可选链调用 host），**不需要**动 pluginOnlyRewrites

### A3. 写路径防护（共享角色不泄漏、不可编辑）
- `addCharacter()`（14905）：push 到 `state.project.characters` 而非合并数组
- `deleteCharacter()`（14942）：`if (character.shared) return;` + filter 回写 project.characters
- `setCharacterField()`（15003）：shared guard
- `hideCharacter/showCharacter/showAllCharacters`（14963/14975/14986）：shared guard（共享角色的显隐由源文件/设置控制，NC 内不提供）
- `uniqueCharacterName()`（24990）：查重基于合并视图（speaker 按名匹配，同名会歧义）
- `renderCharacterCard()`（5568-5602）：shared 角色 4 个字段 disabled、隐藏 Delete/Hide、卡片头加"共享"徽标（canvas.css 加样式 → 跑 build-plugin-styles.cjs）

### A4. 设置项
- `DEFAULT_SETTINGS`（main.js:31-42）+ `normalizeSettings`（1157）加 `sharedCharactersFolder: 'Characters'`；留空 = 禁用
- 设置页 `NarrativeCanvasSettingTab`（1015）加文本项（中英双语按现有 i18n 模式）

### A5. NC 测试与构建
- `tests/fixture-roundtrip.html` 加 fixture：host stub 注入 `loadSharedCharacters`（先例 846-863），断言①合并视图含共享角色 ②`getSavedState().project.characters` **不含**共享角色（防泄漏）
- `tests/gui-regression.html` 加只读标记断言（先例 674-679）
- 构建：`node scripts/build-plugin-bundle.cjs && node scripts/build-plugin-styles.cjs`；`--check` 通过
- 跑通 smoke / fixture-roundtrip / gui-regression 三个浏览器测试（`node scripts/run-browser-test.cjs tests/<page>.html <statusName> 60000`）

## Workstream B: narrative-tool 导出引擎（纯函数 + 命令层）

### B1. export-engine.js
- `exportEngine(json, config)` 支持 `config.externalCharacters: [{id, name}]`
- `resolveCharacter()`（30）：charMap 合并 externalCharacters（project.characters 优先，外部兜底）
- `knownCharacterNames` 构建（207-216）：并入 externalCharacters 的 name——否则 speaker 前缀剥离对共享角色失效，会再次出现"王裕昌: 王裕昌:"双前缀

### B2. commands/shared-characters.js（新模块）
- `loadSharedCharacters(app, folder='Characters')`：扫 vault `Characters/*.md`，解析 frontmatter（`app.metadataCache.getFileCache`），返回 `[{id: 'gc-'+fid, name, role, voice}]`
- 命令层调用点：export-current.js doExport、batch-export.js exportAllDialogues、auto-export.js exportSingleFile（每次导出前加载，三个调用点各加一行 config 透传）

### B3. 测试
- 新 `tests/shared-characters.test.js`：loader 的 frontmatter 解析、gc- 前缀、缺 id/name 退化
- `tests/export.test.js` 或新断言：cast 引用 gc- id + externalCharacters 注入 → 正确解析角色名；externalCharacters 名进入 knownCharacterNames（双前缀不再出现）；project.characters 与 externalCharacters 同 id 时 project 优先
- 全套 `node --test tests/*.test.js` 保持全绿（310 + 新增）
